[!info] 关键参数说明
在这个配置中，有几个关键参数需要特别说明：

参数 说明 推荐值
GPU_MEMORY_UTILIZATION 每个 GPU 预留 15% 显存用于缓存 0.85

enforce-eager 强制使用 eager 模式（RTX 2080 Ti 必选） –

[!tip] GPU_MEMORY_UTILIZATION
设置为 0.85，表示每个 GPU 预留 15% 的显存用于推理过程中的中间结果缓存。这个值需要根据实际模型大小和显卡显存容量进行调整。

[!tip] TENSOR_PARALLEL_SIZE
设置为 2，这是经过计算后的最优值。由于 DeepSeek-R1 的注意力头数量为 16（对于 Qwen 7B），需要能够被 TP 整除，而 8 张显卡用 TP=8 会导致无法整除的错误。

[!tip] enforce-eager
参数强制使用 eager 模式而非 Flash Attention，这是因为 RTX 2080 Ti 不支持 Flash Attention 2.0。

问题二：显存不足（OOM）

当 GPU 显存利用率设置过高时，会出现 out of memory 错误。特别是在处理长文本或高分辨率图像时更容易触发。

[!success] 解决方案

问题三：Tensor Parallel 维度不匹配

[!warning] 错误信息
ValueError: Tensor parallel size (8) must divide attention heads

这是因为模型的注意力头数量无法被 Tensor Parallel Size 整除。

[!success] 解决方案
调整 TP 大小，使其能够整除注意力头数量。对于 DeepSeek-R1-Distill-Qwen-7B（16 个注意力头），可以使用 TP=2 或 TP=4。

问题四：Flash Attention 不兼容

RTX 2080 Ti 使用的 Turing 架构不支持 Flash Attention 2.0，导致推理失败。

性能优化建议

根据我们的实践经验，以下几点可以显著提升推理性能：

[!abstract] 优化策略

1. 批量处理

vLLM 支持连续批处理（Continuous Batching），可以在不增加延迟的情况下提高吞吐量。可以通过调整 max_num_seqs 参数来控制批量大小。

2. 显存管理

对于多卡环境，合理分配显存非常重要。建议预留 10-15% 的显存用于 KV Cache，避免 OOM。

3. 模型量化

如果对精度要求不是特别高，可以考虑使用量化后的模型（如 AWQ、GPTQ），可以在保持较高精度的同时大幅减少显存占用。

4. 通信优化

对于多卡推理，GPU 之间的通信带宽很重要。NVLink 可以显著提升跨卡数据传输速度。
