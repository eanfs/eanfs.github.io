让编程智能体“写”视频：代码出片解决了什么，又没解决什么

资料核验：2026 年 11 月 9 日 17:58—17:59（新加坡时间），依据各项目 GitHub 仓库 README、许可证与 Release 页面。Star 数为该时刻读数，会持续变化。本文是公开资料分析，作者没有运行或测试文中任何工具，也不构成选型背书。

过去一周，开源 AI 视频圈最热闹的方向不是一个新的视频生成模型，而是一种更“笨”的做法：让 Claude Code、Cursor 这类编程智能体写代码，用代码把每一帧画出来，再由 ffmpeg 合成 MP4。

这件事并不新。Manim 用 Python 做数学讲解动画已经很多年，Remotion 也早就能用 React 写视频。新的是写代码的那一方：以前要动画师或工程师逐行写，现在可以用一句话交给智能体，人只负责提要求和拍板。

它值得认真看，是因为它恰好针对生成式视频最头疼的三个问题：一致性、可编辑性和可复现性。但它也有清楚的边界。

一周里冒出来的几种做法

sarpstar/cinecode（MIT，创建于 11 月 3 日，核验时 1759 Star）是这股势头的代表。按照它的 README，智能体会先提问、给出逐秒的节拍表和可逐行修改的“导演卡”，先展示两个场景的静帧供确认，再渲染草稿；每一帧在无头 Chrome 中由代码渲染，快速模式下整部片子是一个自包含的 film.html，场景是时间的函数，画面用 Canvas 2D 或 three.js。它支持 Claude Code 和 Cursor，画面本身不产生模型费用。

围绕它，已经出现了“给人用的那一层”。cinecode-studio（MIT，21 Star）是一个桌面制作面板：写点子、确认带时间的剧本，再由本机的 Claude Code 出片。leodavincs/kurgu（MIT，10 Star）则做成了本地的类 Premiere 剪辑器。

其他项目把同样的思路用在不同题材上：

  • ai-vote-series（9 Star）是一个中文的“观众投票每日动画连载” Claude Skill，画面用 Canvas 2D 逐帧绘制，明确写着不用视频模型；
  • claude-animated-shorts（MIT，2498 Star）在 Remotion 里用 three.js 渲染 55—70 秒的竖屏动画故事短片，同样声明不使用 AI 视频生成器；
  • ultrademo（Apache-2.0，13 Star）让智能体用真实产品界面，把每个场景写成 HTML 与动画代码，做发布片、讲解片和广告。

底层渲染框架也在快速迭代。HyperFrames（HeyGen 组织下的开源项目，Apache-2.0，81326 Star）把自己定位为“写 HTML，渲染视频，为智能体而建”，把 HTML、CSS、媒体和可定位的动画变成确定性的 MP4。

Star 数低的项目只能说明“有人在这么做”，不能证明成熟度或效果。上面的项目大多创建不到一周，应当当作信号而不是结论来读。

代码出片到底解决了什么

一致性：由状态决定，而不是靠运气

用生成模型做连续剧，最常见的翻车是角色“变脸”：发型、衣服、房间布置在两集之间悄悄变了。

ai-vote-series 给了一个很直接的答案：每集一份 state.json，记录主角的发型、胡茬、衣服和房间。README 的说法是，剪过的头发在之后每一集都是短的，“改了不变回去”由程序保证。

这背后的逻辑很朴素：当角色是一段绘图代码加一份参数时，一致性就是一个数据问题，而不是一个抽卡概率问题。

可编辑性：时间线是一个可读的文件

生成式视频的另一个痛点是“只能整段重来”。想把标题放大一点，往往要重新生成，结果连带别处也变了。

kurgu 的设计是把整条时间线放在一个普通的 project.json 里：画布尺寸、帧率，以及视频、图片、文字、色块、音频等图层的时间、位置、淡入淡出、特效和音量包络。智能体写这个文件，人在浏览器里的图层列表、实时预览和属性面板中微调；每次手动修改都会保存回 project.json 并记录到 changes.md，选中对象和播放头位置写入 .kurgu/state.json。因此“把这段字放大”“在这里剪一刀”这样的指令有了明确的对象。按 README 所述，整个流程运行在 127.0.0.1，不上传内容。

cinecode 也有类似的承诺：你的修改意见只改动它涉及的部分。

这对习惯用剪辑软件的人尤其重要。OpenFilm（MIT，5444 Star）在 11 月 9 日发布的 v0.3.1 中加入了导出到 Premiere Pro、Final Cut Pro、剪映和 CapCut 的功能，带完整原始素材和可调整的剪辑余量。智能体做出粗剪，人仍然可以回到熟悉的工具里精修。

可复现性：同样的输入，同样的成片

如果同样的设置每次渲染结果都不同，就很难审片、改片和回溯问题。HyperFrames 在 v0.9.25 的发布说明中写道：每次渲染都为随机值播种，因此用同样设置重新渲染会得到同样的影片。cinecode 的起始模板同样强调确定性时间线和带种子的随机数。

可复现还有一个副作用：项目本身就是文本，可以放进版本管理，改坏了可以撤销。cinecode 的 FAQ 提到，如果本机装了 git，智能体会为影片的文本文件保留本地历史。

它没有解决什么

真实感与真人

代码擅长图形、文字、图表、风格化的 2D 和 3D，但不擅长“看起来像实拍”的真实世界，尤其是真人。cinecode 的 FAQ 说得很坦白：影片越长、越偏重事实，就会有越多真实素材加入，来自开放档案馆和图库，并逐项登记授权；人脸在特写中以风格化或剪影方式呈现效果最好；接入图像或视频生成器只在用户要求时作为最后手段。

换句话说，代码出片不是生成式视频的替代品，而是另一种取舍：用“写实感”换“可控性”。

智能体的会话成本与电脑性能

“不产生模型费用”指的是画面不调用视频生成模型，不等于零成本。编程智能体本身的订阅或用量会随片子变长而增加，cinecode 也写明影片越长，所需时间和用量越多。渲染端，cinecode 建议使用较新的 Mac 或显卡驱动正常的 PC，无头 Chrome 没有 GPU 时会退回 CPU，测试可以，渲染整片就太慢了。claude-animated-shorts 则提醒，每次 Remotion 打包都会把约 1.3 GB 的 public/ 复制到临时目录。

审美仍然要人来拍板

这些项目几乎都把人的确认放在关键节点：cinecode 先给静帧再动工，ultrademo 有可在画面上框选批注的审阅页，并会把文案中找不到出处的说法先列出来请你确认。智能体能把执行速度提上去，但“这条片子好不好”“这句话能不能说”依然需要人判断。

早期项目的工程风险

上面多数项目都很新，接口和文件格式可能很快变化。另一个方向的例子是 ComfyUI-H3-Continuity-Studio（MIT，160 Star）。它服务的是 MiniMax H3 生成模型，在 v0.20.0 中新增了独立的 MCP 适配器，用 21 个工具把项目、渲染规划和版本开放给 Codex、Claude Code 等智能体。它的发布说明相当诚实：客户端里的技能自动激活尚未验证，这一版也没有执行实际的 GPU 渲染。这类说明值得每个选型者认真读。

选型前先问自己四个问题

以下是阅读这些项目资料后整理的判断框架，不是测试结论。

  1. 内容是否以图形、文字和图表为主？ 讲解片、数据视频、产品演示、风格化的系列动画，最适合代码出片；需要真人表演或写实场景的，仍然更依赖实拍或生成模型，代码层更适合做字幕、图表和包装。
  2. 你需要在哪里修改？ 习惯直接对智能体说话，可以从 cinecode 这类“一句话出片”的工具开始；想像剪辑软件一样逐层调整，看 kurgu 这种时间线即文件的设计；最终要回到剪映或 Premiere 精修，就关注 OpenFilm 的导出能力。
  3. 是否是连续内容？ 系列片的关键是把角色、格式和风格写成可保存的状态。ai-vote-series 的状态文件、cinecode 的“保存格式做下一集”都是这个思路。
  4. 许可证和素材授权是否清楚？ 开源不等于随便商用。Remotion 的许可证允许个人、3 名员工以内的营利组织和非营利组织免费使用，更大规模的营利组织需要公司许可；ai-vote-series 的 scripts/ 和 engine/ 为 MIT，其余内容为 CC BY-NC 4.0；HyperFrames 的 Studio 应用可免费使用，其 Pro 计划另外接入 HeyGen 的视频、图像、声音和音乐模型。素材、字体、音乐与声音克隆也各有授权要求。发布前请逐项回到原始许可页面核对。

如果你想试一下，比较稳妥的起点是做一条自己完全掌握事实的 30 秒讲解片：内容不涉及真人、素材全部自有或明确授权，先看静帧再渲染，并记录下智能体用量和渲染时间。这样得到的经验，比任何 Star 数都更能说明这条路是否适合你。

结语

“视频即代码”把视频从一次性的生成结果，变回了可以阅读、比较、修改和重放的工程产物。这正是生成式视频在一致性、可编辑性和可复现性上的短板所在。

但它解决的是“可控”，不是“逼真”。在讲解、系列动画和产品演示这些场景里，它可能已经比抽卡更实用；在需要真实世界质感的地方，它更像是生成模型和实拍素材外面的那一层骨架。理解这一点，比追逐本周哪个仓库涨得最快更重要。
